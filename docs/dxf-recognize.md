# DXF 截面识别链路

把 AutoDie（口模智造）里跑通的 DXF 识别链路抽成独立库，脱离浏览器也能用：**一张 DXF → 产品外轮廓 + 内孔**。

- 来源：`C:\Users\李\Desktop\自动画图`（2026-11-16 版本，含 `G.chain` 图行走重写）
- 代码：`lib/dxf/{parse,geom,profile}.mjs`，CLI：`scripts/dxf_profile.mjs`
- 依赖：Node 18+ / 浏览器，零第三方依赖

## 用法

```bash
node scripts/dxf_profile.mjs 图纸/-6.1.dxf
node scripts/dxf_profile.mjs 图纸/-6.1.dxf --json
node scripts/dxf_profile.mjs 图纸/1106-02.dxf --svg out/preview.svg
node scripts/dxf_profile.mjs 图纸/某图.dxf --scale 2      # 1:2 图纸放大到实际尺寸
```

输出示例（`-6.1.dxf`）：

## 两段式结构

```
DXF 文本 ──parse()──▶ 闭合环（几何事实）──recognize()──▶ 产品截面（业务判断）
```

| 阶段 | 回答的问题 | 失败表现 |
| --- | --- | --- |
| `parse()` | 图里有哪些闭合环？尺寸多少？ | 0 环（线条断开）、环数偏多（图框/标注也成环） |
| `recognize()` | 哪一个环才是产品截面？ | 把图框当产品、选中了别的视图、内芯丢失 |

职责分开才能分别回归：**几何错了看 parse，视图选错看 recognize**。

## 判定顺序（不可调换）

1. **图框剔除**：几乎占满图幅、点数 ≤12 的简单环只是候选；必须有旁证才剔 —— 图里有文字/标注、框内 ≥2 个图形、或框面积比内部图形大 15 倍。否则保留为产品轮廓（带内孔的板就是这种）。
2. **视图聚类**：按外包框邻近（间距 < max(3mm, 6% 尺寸)）把同一视图的轮廓并成一簇，取最大簇。
3. **框中框**：主轮廓是轴对齐矩形（≤8 点）且内含 ≥2 组同尺寸图形 → 判为排版图框，改取最大一组。
4. **角色重判**：簇内面积最大者为 `outer`，其余完全落在外轮廓内为 `hole`，否则 `outer`。
5. **居中**：主视图平移到原点，`bbox/area/perimeter` 同步重算。

## 已知限制

- **只吃 ASCII DXF**；二进制 DXF 直接抛错提示另存。
- **DWG 不处理**：AutoDie 的 DWG 直读依赖 `server.mjs` + LibreDWG WASM，未纳入本仓库。需要时先用 CAD 另存 DXF。
- **块只展开 4 层**（`INSERT` 递归上限），超出部分按原样跳过。
- **SPLINE 用 NURBS 求值**，knots 不完整时退化为控制点折线，曲线可能偏离实际。
- **缺口桥接有上限**：阶梯容差最大到图面尺寸 2%（且 ≥0.5mm），更大的断口不会自动连，会返回 0 环。
- **单位只认 `$INSUNITS`**，老图纸不写这个头时按 1:1 处理，可用 `--scale` 手工纠正。
- **图框判定是启发式**：极端排版（如无文字的纯表格图框）可能误留或误删，结果里 `aux` 轮廓仍保留，可人工改回。

## 背景：为什么链条长这样

- **贪心拼接会拆断轮廓**：端点精确时，共享顶点会让一条闭合环被切成两条开口链，表现为内芯凭空消失；改成端点聚类 + 邻接图行走才稳定。
- **图框不能一刀切删**：单个大矩形可能就是产品本身，必须有文字/多图形/面积悬殊这类旁证。
- **先量化再判断**：图元数、类型、外包尺寸对不上时，问题在解析层，不用往下看识别。

相关工具：[`dxf_stats.py`](dxf-stats.md) 先做批量体检，再用本链路看轮廓。
