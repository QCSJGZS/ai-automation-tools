# dxf_batch.mjs —— 批量识别与 CSV 报告

把一个目录（含子目录）里的 DXF 一次性识别完，产出可直接用 Excel 打开的 CSV：

```bash
node scripts/dxf_batch.mjs D:\图纸
node scripts/dxf_batch.mjs D:\图纸 --csv out\2026-11.csv
node scripts/dxf_batch.mjs D:\图纸 --flat --limit 20 --json
```

默认报告路径 `out/dxf-report.csv`（`out/` 已在 .gitignore 里）。

## 选项

| 选项 | 说明 |
| --- | --- |
| `--csv <path>` | 报告路径，默认 `out/dxf-report.csv` |
| `--json` | 结果同时打到 stdout（`status` 保持稳定 token） |
| `--flat` | 只扫当前目录，不进子目录 |
| `--limit N` | 最多处理 N 个文件 |
| `--no-bom` | 不写 UTF-8 BOM（默认写，Excel 打开中文不乱码） |
| `--quiet` | 不打印逐个文件进度 |

## 退出码

| 码 | 含义 |
| --- | --- |
| 0 | 全部处理完成且有识别成功项 |
| 1 | 有文件报错，或没有任何文件识别成功 |
| 2 | 参数或路径错误 |

适合放进批处理/CI：非 0 就意味着有图需要人工看一眼。

## CSV 列

| 列 | 含义 |
| --- | --- |
| 文件 | 相对扫描目录的路径（保持子目录层级） |
| 状态 | 成功 / 无闭合轮廓 / 报错 |
| 轮廓数 | 有效轮廓条数（外轮廓 + 内孔） |
| 外轮廓面积mm2 | 所有 outer 面积之和 |
| 外轮廓宽mm / 高mm | 有效轮廓整体外包框 |
| 内孔数 | role = hole 的条数 |
| 净面积mm2 | 外轮廓面积 − 内孔面积 |
| 轮廓点数 | 有效轮廓的顶点总数（异常偏大说明离散过密） |
| 图元数 | 原始 DXF 图元数 |
| 单位系数 | `$INSUNITS` 换算到 mm 的系数 |
| 说明 | 识别备注与警告（如「已忽略图框/其它视图 N 条」） |

`--json` 时 `status` 为 `ok` / `empty` / `error`，便于程序判断；CSV 里转成中文给人看。

## 行为约定

- **只收 `.dxf`**，大小写不敏感；其它扩展名忽略。
- **单张图失败不中断整批**：报错写进该行 `说明`，最后汇总。
- **不改动输入文件**；报告目录自动创建。
- 排序按路径字典序，便于两次报告 diff。
- 一个文件只出一个状态：能识别就 `成功`，即使有缺口桥接警告（警告写在 `说明` 里）。

## 已知限制

- 与 `dxf_profile.mjs` 共用同一套链路，**继承其全部限制**：只吃 ASCII DXF、INSERT 4 层、缺口语义、单位只认 `$INSUNITS`。
- 串行处理，无并发；几万张图请分目录跑或用 `--limit` 分批。
- CSV 里不做公式与样式，复杂汇总请在 Excel/脚本里二次处理。

## 与 dxf_stats 的分工

| 工具 | 回答的问题 |
| --- | --- |
| `dxf_stats.py` | 这张图**里面有什么**（图元、图层、类型） |
| `dxf_batch.mjs` | 这批图**识别出了什么**（轮廓、面积、尺寸、成功与否） |

先跑 stats 定位「解析层是否正常」，再跑 batch 看「识别结果是否合理」。
